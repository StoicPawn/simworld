# Control Tower and causal technology effects

## Goal

A mature SimWorld run must be reproducible and highly configurable without editing simulation code. The **Control Tower** is the declarative experiment surface. It controls initial conditions and possibility spaces; it must not prescribe historical outcomes.

A world configuration may choose or override:

- simulation seed and horizon;
- map source, dimensions, resolution and map seed;
- initial population amount and placement/distribution;
- resource layers and local overrides;
- which technical affordance catalogs exist in that universe;
- enabled/disabled technical possibilities;
- knowledge present at time zero;
- model parameters and future module toggles;
- later: climate regime, species definitions, biological parameters, cultural priors, institutions present at start, observation/logging resolution, LLM policy, experiment batches and counterfactual interventions.

The Control Tower is configuration, not causal state. A parameter such as `enabled technology` means the possibility exists in that universe; it does **not** mean anybody has discovered it.

## Technology must alter causal equations

A technical discovery is not useful if it is only an event label. Every technical affordance may expose generic **effect channels**. Examples:

- `cultivation_output`;
- `storage_preservation`;
- `construction_productivity`;
- `combat_effectiveness`;
- `record_persistence`;
- `transmission_fidelity`;
- `claim_credibility`;
- transport/information/energy channels added later.

Simulation domains consume those channels inside their existing equations. The technology layer therefore never contains historical functions such as `iron_wins_battle()` or `writing_makes_story_true()`.

Effects are actor-local and context-dependent:

```text
capability exists in catalog
        !=
actor has discovered capability
        !=
actor masters capability
        !=
actor has required equipment/material
        !=
effect applies in this event
```

Mastery scales effect strength. Context gates applicability. Some effects can be probabilistic.

## Writing example

`durable_symbolic_recording` can increase record persistence and transmission fidelity when a record is actually created/preserved/read. It can sometimes increase the credibility of a claim to a reader who accepts that medium.

It never makes a narrative true. A written lie can become persistent and credible. A true oral account can remain more trusted than a dubious document. This preserves the existing rule:

`document != truth`.

## Iron example

A capability such as `worked_iron_tools` can affect cultivation, construction and combat channels only when suitable equipment is materially available to the actor/group using it. Knowing ironworking does not magically strengthen every descendant, organization or army.

The eventual outcome still depends on terrain, numbers, logistics, health, organization, information, morale, leadership and other modeled factors.

## Scalability rule

Technology-specific effects live primarily in versioned data catalogs. The engine understands generic effect channels and requirements. Adding a future technique should normally mean adding data, not adding a special historical branch to the simulator.

## Long-term Control Tower

The target interface is a validated world blueprint that can be edited manually, generated by a UI, or composed programmatically. Eventually the same schema should drive:

- one-off fictional worlds;
- batch Monte Carlo experiments;
- historical initial-condition reconstruction;
- controlled counterfactuals;
- inverse-inference experiments;
- real-world geopolitical scenarios.

The UI can become very rich, but the underlying source of truth should remain a portable versioned configuration document so every run is inspectable and reproducible.
